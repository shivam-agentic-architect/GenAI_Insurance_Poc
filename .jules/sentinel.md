## 2024-05-24 - DoS Risk in Upload Endpoint and Information Leakage on 500 Errors
**Vulnerability:** The `/api/upload` endpoint had no size limit configured in `multer`, allowing potentially massive file uploads. Furthermore, the cleanup code (`fs.unlinkSync`) was placed at the end of the `try` block and would be bypassed if an error occurred during text extraction or embedding, leading to disk exhaustion on the server (Denial of Service). Additionally, 500 error catch blocks leaked raw `error.message` data.
**Learning:** Temporary files from uploads (like via `multer`) must be cleaned up in a `finally` block to ensure they are removed regardless of success or failure. Error responses should never leak raw exception messages which might contain stack traces, internal paths, or database errors.
**Prevention:** Always use `limits: { fileSize: ... }` with `multer`, and always wrap processing of temporary files in a `try...finally` block. Return generic error messages (e.g. "Failed to process file") for unhandled 500 errors.
