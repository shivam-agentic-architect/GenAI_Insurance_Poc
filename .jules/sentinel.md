## 2024-05-15 - [Resource Exhaustion & Info Leakage via File Uploads and Error Messages]
**Vulnerability:** The `/api/upload` endpoint processed file uploads without file size limits on multer and didn't guarantee the cleanup of temporary files created during processing if an error occurred early. Furthermore, `server.ts` returned raw `error.message` strings directly to the client on 500 statuses.
**Learning:** File uploads are prone to Denial of Service / resource exhaustion if arbitrary size files are allowed to be saved to disk, and if cleanup logic isn't wrapped in a `try...finally` block. Returning `error.message` strings leaks sensitive internal backend information to clients.
**Prevention:** Always set explicit size limits on multer. Wrap any temporary resource operations (like file uploads) in a `try...finally` block to ensure cleanup code (like `fs.unlinkSync`) always runs regardless of exceptions. Always sanitize error messages returned to clients using generic HTTP 500 error messages instead of raw stack traces or internal variable messages.
