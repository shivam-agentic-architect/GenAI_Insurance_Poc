## 2024-05-14 - [HIGH] Fix file upload DoS, path exhaustion, and info leak
**Vulnerability:** The application was vulnerable to DoS due to missing file size limits on `multer` uploads. Additionally, the `/api/upload` endpoint could cause disk exhaustion if an uploaded file was not an allowed type, because cleanup was done inside the `try` block, which was skipped on early `return` paths. Finally, internal server paths and error details were exposed in the API response if an error occurred in `/api/upload` or `/api/gpt/ask`.
**Learning:** Always use `limits` when using `multer` to prevent malicious large file uploads. Temporary files must *always* be cleaned up, preferably using a `finally` block, to guarantee execution regardless of return or throw. Never pass `error.message` directly in external API responses for 500 statuses.
**Prevention:** Configure size limits on file uploads. Implement `try/finally` blocks specifically for cleaning up temporary files. Use generic error messages for 500 API responses to avoid leaking details.
