## 2025-02-28 - Missing Upload Size Limit and File Cleanup leading to DoS
**Vulnerability:** The `/api/upload` endpoint in `server.ts` lacked a file size limit in its `multer` configuration, allowing for arbitrarily large files to be uploaded. Furthermore, if file processing failed (e.g., due to an unsupported file type or empty content), the uploaded file was not deleted from the `uploads/` directory, causing persistent disk consumption.
**Learning:** File uploads are inherently risky and must be bounded by size limits to prevent Denial of Service (DoS) attacks via memory or disk exhaustion. Additionally, cleanup logic must be fail-safe; placing cleanup logic only on the "happy path" leaves temporary files lingering on the server if an error occurs.
**Prevention:** Always configure `multer` (or any upload middleware) with a `limits: { fileSize: MAX_BYTES }` configuration. Ensure that temporary file cleanup is placed in a `finally` block or handled via dedicated middleware so that it executes regardless of whether processing succeeds or fails.
