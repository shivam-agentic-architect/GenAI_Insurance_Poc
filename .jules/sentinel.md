## 2024-05-24 - [Unbounded File Uploads & Temp File Leak]
**Vulnerability:** File upload endpoint (`/api/upload`) lacked file size limits, and `fs.unlinkSync` for temp file cleanup was only executed at the end of the `try` block. Additionally, error messages leaked `error.message` directly to the client.
**Learning:** `multer` requires explicit file size limits to prevent DoS attacks. Temp files created by `multer` must be cleaned up in a `finally` block to guarantee execution even if parsing (e.g. PDF generation) or embedding API calls fail, otherwise disk space will eventually exhaust. Exposing `error.message` on a 500 response reveals internal stack traces or external API secrets.
**Prevention:** Always configure `multer({ limits: { fileSize: LIMIT } })`. Use a `try...finally` pattern with `if (req.file && fs.existsSync(req.file.path)) fs.unlinkSync(req.file.path)` for file cleanup. Return generic error messages (e.g. "Failed to process file") on the backend to avoid info leakage.
