## 2024-05-18 - Missing finally blocks and sensitive error leakage in file upload endpoints
**Vulnerability:** File upload endpoints (`/api/upload`) lacked a `try...finally` block around file processing. Unsupported file types triggered an early return or processing errors could be thrown, skipping `fs.unlinkSync` and leading to resource exhaustion (disk filling up with temporary files). Additionally, `error.message` was sent in 500 error responses, potentially leaking sensitive paths or logic details.
**Learning:** File system operations and temporary files must ALWAYS be cleaned up in a `finally` block to ensure execution regardless of success, failure, or early returns. Error details must be logged securely and hidden behind generic messages on the API surface.
**Prevention:** Always wrap temporary file operations (like `multer` files) in a `try...finally` block. Use generic error responses (e.g., "Failed to process file") for unhandled server errors instead of `error.message`.
