## 2024-05-24 - [Resource Exhaustion & Information Leakage in RAG Server]
**Vulnerability:** The `/api/upload` endpoint in `server.ts` allowed arbitrarily large file uploads and did not guarantee temporary file cleanup if an error occurred during PDF parsing. Additionally, both `/api/upload` and `/api/gpt/ask` endpoints leaked raw `error.message` details to the client on HTTP 500 errors.
**Learning:** File upload endpoints must explicitly restrict file size (e.g., using `multer`'s `limits`) and guarantee file cleanup using `try...finally` blocks to prevent disk space exhaustion (DoS). API endpoints must also return generic error messages for unhandled exceptions to prevent information leakage that could expose internal paths, dependencies, or logic.
**Prevention:** Always configure size limits on `multer` upload handlers. Utilize `try...finally` to ensure temporary files are deleted via `fs.unlinkSync` regardless of processing success or failure. Standardize 500 error responses to use generic string messages instead of passing through error objects.
