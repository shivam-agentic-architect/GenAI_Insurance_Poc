## 2024-03-24 - [Resource Exhaustion & Info Leakage]
**Vulnerability:** The `/api/upload` endpoint lacked a file size limit for uploaded files and relied on the standard flow for cleanup. It could crash the server with huge files (DoS) and leak resources if an error occurred before `fs.unlinkSync` was called. Also, `500` errors in both `/api/upload` and `/api/gpt/ask` leaked raw `error.message` contents back to the client.
**Learning:** `multer` defaults to unbounded file sizes if not configured, allowing for DoS via resource exhaustion. Also, always ensure file system cleanup happens in a `finally` block because operations on the file before cleanup might throw. Lastly, generic errors should always be returned for HTTP 500s rather than internal application error traces to prevent exposing server details to users.
**Prevention:** Always configure `limits: { fileSize: ... }` when using `multer`. Always wrap temporary file handling logic in a `try...finally` block to guarantee cleanup, and return sanitized, generic error responses from API handlers for server-side exceptions.
