## 2024-05-15 - Unbounded File Uploads and Info Disclosure
**Vulnerability:** The application accepts uploaded files of unlimited size, risking Denial of Service (DoS) via disk exhaustion or memory exhaustion. Furthermore, the uploaded file might not be cleaned up if a failure happens during RAG embedding parsing, exacerbating disk usage. Lastly, the server returns unhandled `error.message` on exceptions for file upload and `/api/gpt/ask` requests, risking Information Disclosure of internal file paths, API errors or configuration.
**Learning:** Default configuration for multer and lack of `finally` blocks in node handlers can cause server crashes from unhandled large inputs, and naive exception handlers can leak environment details.
**Prevention:** Always specify an explicit `limits: { fileSize: X }` on file upload middleware. Wrap temporary file handling inside `try...finally` to ensure `fs.unlinkSync` cleans up artifacts regardless of whether processing succeeded or failed. Never return `error.message` verbatim in production HTTP responses.
