## 2024-06-24 - File Upload DoS and Info Leakage
**Vulnerability:** The `/api/upload` endpoint allowed unbounded file uploads which could exhaust server resources (DoS). If an error occurred during parsing, uploaded files remained on disk permanently, causing storage exhaustion. Additionally, the `/api/upload` and `/api/gpt/ask` API endpoints returned raw `error.message` data to clients on HTTP 500.
**Learning:** `multer` defaults to unbounded sizes if not explicitly restricted. Files mapped to request objects must be cleaned up reliably, regardless of downstream errors. Returning raw error messages is a common oversight that leaks stack details and internal workings.
**Prevention:** Always set `limits: { fileSize }` when configuring `multer`. Wrap file-handling logic in `try...finally` blocks, and clean up temporary files in the `finally` execution. Always return generic error responses (`res.status(500).json({ error: "Internal error" })`) while logging the original error server-side.
