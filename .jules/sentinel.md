## 2024-05-18 - [Multer File Upload DoS and Information Leakage]
**Vulnerability:** The `/api/upload` endpoint used `multer` without limits, which could lead to a Disk Exhaustion DoS attack via extremely large files. Furthermore, if errors were encountered during PDF parsing, the endpoint responded with `error.message` (leaking internal execution details) and failed to clean up the temporary uploaded file from the disk, exacerbating the DoS risk.
**Learning:** File upload endpoints must always have strict `fileSize` limits configured in `multer`. File cleanup must be guaranteed using `try...finally` blocks to ensure temporary files are deleted even if internal processing (like PDF parsing or vector embedding) fails. API endpoints should not leak raw `error.message` details to the client.
**Prevention:** Configure `multer({ limits: { fileSize: LIMIT } })` and wrap endpoint logic in `try { ... } finally { fs.unlinkSync(tempFile) }` blocks, while providing generic, static error responses to clients.
