## 2024-07-26 - [HIGH] Fix resource exhaustion and info leakage in endpoints
**Vulnerability:** The `/api/upload` endpoint allowed arbitrarily large file uploads because `multer` had no size limits configured. Furthermore, when parsing exceptions occurred or early returns were triggered, the temporary uploaded file was never deleted, leading to resource exhaustion (DoS) over time. Additionally, the `/api/upload` and `/api/gpt/ask` endpoints leaked internal error details to the client (`error.message`).
**Learning:** Temporary files created by middleware like `multer` require guaranteed cleanup using `try...finally` blocks, as early returns or unhandled exceptions will otherwise leave orphaned files on disk. Error handling must always sanitize messages before returning them to clients to prevent leaking stack traces or internal implementation details.
**Prevention:** Always configure `limits: { fileSize: X }` on file upload middleware. Use a `try { ... } finally { fs.unlinkSync(...) }` pattern for all temporary file processing to ensure robust cleanup. Always return generic error messages for HTTP 500 status codes.
