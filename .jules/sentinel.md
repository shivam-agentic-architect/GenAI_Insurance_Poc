## 2024-05-24 - [Information Leakage and Resource Exhaustion in API]
**Vulnerability:** The `/api/upload` endpoint was missing a file size limit in its `multer` configuration, creating a Denial of Service (DoS) vulnerability via disk exhaustion. It also lacked a `try...finally` block to guarantee the deletion of temporary files if an exception occurred during processing. Additionally, both the upload and RAG endpoints (`/api/gpt/ask`) were exposing raw `error.message` data on HTTP 500 responses, potentially leaking sensitive paths or API errors.
**Learning:** File upload endpoints must always strictly bound file sizes and ensure reliable cleanup of temporary artifacts. Server errors must never be directly forwarded to clients to maintain a secure boundary and prevent information leakage.
**Prevention:** Always use `limits: { fileSize: MAX_SIZE }` in multer. Wrap temporary file handling in `try...finally` structures. Always use generic error messages for unhandled 500 status responses on external facing APIs.
