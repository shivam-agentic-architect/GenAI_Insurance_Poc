## 2024-05-15 - [HIGH] Prevent Disk Exhaustion DoS in File Uploads
**Vulnerability:** The `/api/upload` endpoint using `multer` lacked a file size limit (`limits: { fileSize: ... }`). Additionally, the file deletion `fs.unlinkSync(file.path)` was located at the end of the `try` block, meaning any error during file processing (like PDF parsing) would skip the cleanup, leading to abandoned temporary files and eventual disk exhaustion.
**Learning:** File uploads represent a significant DoS vector if limits aren't enforced. Furthermore, temporary resources (like uploaded files on disk) must *always* be cleaned up in a `finally` block to ensure release even when errors occur.
**Prevention:** Always configure `limits` when using `multer`. Always use a `try...finally` block for cleaning up temporary files (`req.file.path`) generated by upload middlewares.
