## 2024-05-24 - [DoS Risk via File Uploads and Info Leaks]
**Vulnerability:** The `/api/upload` endpoint allowed unrestricted file sizes and lacked guaranteed file cleanup (`finally` block) if an error occurred during PDF parsing or embedding generation. This could lead to a Denial of Service via disk exhaustion. Additionally, raw `error.message` data was returned in 500 responses in `/api/upload` and `/api/gpt/ask`, leaking internal server details.
**Learning:** File processing tasks that involve external libraries (like `pdf-parse`) or APIs (like OpenAI embeddings) are prone to failures. Relying on synchronous, bottom-of-block cleanups (`fs.unlinkSync`) without a `finally` block creates a severe risk of orphaned temporary files and disk exhaustion.
**Prevention:** Always configure `multer` with sensible `limits.fileSize`. Always handle temporary file cleanup within a `try...finally` block. Never return raw exception details to the client; provide generic error messages and log the details securely on the server.
