## 2024-07-24 - [Resource Exhaustion via Uncleaned Temporary Files and Information Leakage]
**Vulnerability:** The `/api/upload` endpoint processed file uploads without guaranteeing temporary file cleanup in failure scenarios (missing `try...finally`), leading to potential resource exhaustion (Disk space DoS). The multer configuration also lacked file size limits. Additionally, 500 error handlers for the API endpoints were leaking raw internal stack or generic exception messages directly to the client (`error.message`).
**Learning:** In the Node/Express backend `server.ts`, error paths in file handling endpoints will orphan `multer`-created files in the `uploads/` directory if file operations (like `fs.readFileSync` or parsing with `pdf-parse`) fail before reaching explicit `fs.unlinkSync` calls. Furthermore, blindly relying on standard error message passthroughs to clients exposes backend context.
**Prevention:** Always use `limits.fileSize` when configuring `multer`. For temporary file processing, wrap operations involving local file creation in a `try...finally` block to guarantee robust cleanup using `fs.unlinkSync` inside the `finally` block (verifying existence with `fs.existsSync`). For backend APIs, ensure that `catch (error)` blocks obfuscate the original error and send back generic error strings for client-facing 5xx responses.
