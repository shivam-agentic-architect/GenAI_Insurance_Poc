## 2024-08-09 - Missing Try-Finally Cleanup & Information Leakage in Endpoints
**Vulnerability:** File upload endpoints (like `/api/upload` in Node) failed to use a `try...finally` block for deleting temporary files via `fs.unlinkSync()`. This causes temporary files to accumulate when exceptions occur (e.g., unsupported format, processing failure), leading to resource exhaustion (DoS risk). Additionally, `try...catch` blocks in both `server.ts` and `app/main.py` explicitly returned `error.message` or `str(e)` in 500 error responses, exposing stack traces and internal file paths/logic to clients.
**Learning:** File system operations on uploads must guarantee cleanup regardless of the execution path. Generic exceptions often contain sensitive context that should not be forwarded directly to the HTTP response.
**Prevention:** Always wrap temporary file processing in a `try...finally` block and assert that cleanup functions execute in the `finally` block. Never use raw exception details as the body of an HTTP 500 status response; sanitize the response to generic, opaque error messages.
